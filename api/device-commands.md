# USB HID 命令契约

## 传输和帧

| 项目 | 契约 |
| --- | --- |
| USB 标识 | VID `0x0716`、PID `0x5060`；按接口路径唯一选择 |
| 工作模式 | 普通遥测与 DFU 分开使用；进入 DFU 的人工操作见原应用 / 设备说明 |
| 协议帧 | 64 字节；HIDAPI 输出额外前缀 Report ID `0`，输出计数通常 65 |
| 输入适配 | 64 字节，或 `00` + 64 字节；空输入表示暂无数据 |
| 头与负载 | `FF 55`；偏移 8 命令，9 长度，10…61 负载及零填充 |
| 字节序 | 地址、长度及数据结构的多字节整数均为小端 |
| 校验 | 62 = `sum(frame[8:62]) & 255`；63 = `sum(frame[:62]) & 255` |
| 时间字段 | 偏移 2…7 为主机毫秒 tick 的派生值，编码见 `build_frame` |
| 超时 | 参考 `Protocol` 默认 1000 ms，允许 1…60000；单个批量读的所有包共用截止时间 |
| 并发 | 同一接口串行事务；协议未发现可关联请求 / ACK 的请求 ID |

[完整字节表](../docs/protocol.md#64-字节帧)；[构造与解析函数](../k2up/protocol.py)。

## 命令总表

“读”表示不改写 Flash，“控制”仍会改变设备会话或批次状态。请求中的 `U32 / U16 / U8` 表示小端 uint32 / uint16 / uint8。

| 十进制 / 十六进制 | 名称 | 模式 / 性质 | 请求负载 | 响应 | 调用前提 / 后续 |
| --- | --- | --- | --- | --- | --- |
| 3 / `0x03` | 握手 | DFU / 控制 | 空 | 命令 2 ACK | 名称与信息读取前调用；不自动进入 DFU |
| 5 / `0x05` | 开启批次 | DFU / 控制 | 空 | 命令 2 ACK | 擦除或写入前调用；完成后用 4 关闭 |
| 4 / `0x04` | 关闭批次 | DFU / 控制 | 空 | 命令 2 ACK | 汇总确认，不代替逐字节读回 |
| 8 / `0x08` | 擦除扇区 | DFU / 写 | 地址 U32 | 不等待单扇区 ACK | 已开批次；地址必须来自合法范围；成功发送不表示擦除已验证 |
| 9 / `0x09` | 写内存 | DFU / 写 | 地址 U32 + 长度 U8 + 最多 40 字节数据 | 不等待单包 ACK | 已擦除、已开批次；完成后关批次并完整读回 |
| 10 / `0x0A` | 短读取 | DFU / 读请求 | 地址 U32 + 长度 U8 | 同命令数据包 | 正式 `read_marker` 固定读 4 字节；40 / 48 / 52 字节研究读取未成为正式 SDK 通用方法 |
| 11 / `0x0B` | 批量读取 | DFU / 读请求 | 地址 U32 + 长度 U16 | 多个命令 11 包，每包最多 40 字节数据 | 正式方法每次 1…1024 字节；尾包必须等于剩余长度 |
| 21 / `0x15` | 设备日志 | DFU / 设备主动上报 | 设备发送级别 U16、序号 U16、长度 U8、ASCII 文本 | 无主机 ACK 契约 | 等待期间忽略此类日志包，不当成业务响应 |
| 22 / `0x16` | 重置日志状态 | DFU / 控制 | 空 | 命令 2 ACK | 擦写事务前清理状态；不是擦除命令 |
| 23 / `0x17` | 结束会话 | DFU / 控制 | 空 | 命令 2 ACK | 只在成功读回 / 提交之后发送；异常后不自动收尾 |
| 26 / `0x1A` | 普通遥测报告 | 普通模式 / 被动读 | 无主机请求 | 设备主动发送 64 字节报告 | 直接读取；不先握手、开批次或发升级命令 |
| 1 / `0x01` | 设备错误 | DFU / 响应 | 设备错误负载 | — | 收到即停止；含义更细的错误码尚未完整识别 |
| 2 / `0x02` | 成功 ACK | DFU / 响应 | 当前实现不规定 ACK 负载结构 | — | 只用于需要 ACK 的控制命令，不能复用旧 ACK |

## 批量读取示例

请求应用起点 16 字节：负载为 `00 38 00 08 10 00`，对应 `<IH` 的地址 `0x08003800` 和长度 16。帧命令为 11，负载长度为 6。预期单个命令 11 回包，负载恰好 16 字节。

```python
import struct
from k2up.protocol import build_frame, parse_frame
request = build_frame(11, struct.pack('<IH', 0x08003800, 16), tick=0)
assert parse_frame(request).payload.hex() == '003800081000'
```

实际 transport 必须处理 Report ID。帧有效只证明编码 / 校验有效，不证明设备允许读取该地址。

## 地址与长度单位

| 对象 | 地址 | 有效字节 / 分配字节 |
| --- | --- | --- |
| 名称 | `0x08001400` | 读取 256；三个 NUL 结尾字符串 |
| 信息 | `0x08003000` | 读取 1024；摘要用于身份绑定 |
| 应用 | `0x08003800` | 正文长度可变；配置 447 × 2048 字节，结束 `0x080E3000` |
| 提交标记 | `0x08004400` | 4；正文偏移 `0xC00` |
| 背景 | `0x080C6800` | 115208 / 116736 |
| E-Mark 复制 | `0x080E3000` | 66 / 2048 |
| E-Mark 集合 | `0x080E3800` | 666 / 2048 |
| 表盘参数 | `0x080E4000` | 400 / 2048 |
| 开机图 | `0x080E4800` | 110458 / 110592 |

应用备份范围包含背景分配区，但不包含 E-Mark、表盘参数和开机图。它不是所有资源的总备份。

## 普通遥测输出

`decode_report(raw, elapsed)` 返回 `Sample`，其中 `time` 为电脑经过秒数，`voltage` 为 V，`current` 为有符号 A，`power` 为非负 W，`signed_power` 为有符号 W；`temp_in / temp_out` 为 °C 或 `None`，`dp / dn` 为 V，`ah / wh` 为设备累计 Ah / Wh，`record_seconds / uptime` 为设备秒数，`group` 为从 1 开始的组号，`segment` 初始 0。

非遥测包返回 `None`；坏校验或非法测量值抛异常，不应补成有效零值。字段偏移见 [调查](../docs/k2-monitor-research.md#官方程序证据)。

## 失败契约与版本范围

错误 ACK、坏帧、意外命令、超时、短读或短写使当前事务失败。禁止盲目重试、复用剩余 ACK、并发事务或在失败后自动发送 23。已擦除后的失败可能留下不完整应用。

短读取 52 字节与大于 1024 字节批量请求属于特定 Bootloader 的研究结果，不是跨版本接口保证。参考 SDK 保持保守长度；大请求工具会核对 Bootloader 摘要。单台实测不能覆盖全部 K2 修订。

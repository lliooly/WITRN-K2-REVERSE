# 05：普通遥测、电脑记录与文件交换

## 与 DFU 的关系

普通模式直接读取 HID 报告，既有官方采集循环没有遥测启动写命令。它与升级 DFU 是不同用途：共用设备接口不意味着应先发送升级握手或批次命令。

## 原生函数证据

| WITRN PC V1.0.4 地址 | 职责标签 | 支持的结论 |
| --- | --- | --- |
| `0x140014F60` | 采集循环 | `hid_read_timeout` 被动读取 |
| `0x140014DA0` | 报告解析 | 至少 64 字节，偏移 8 的 `0x1A`，功率用电压乘电流绝对值 |
| `0x1400BA290` | CSV 导出 | BOM、元信息、可选列、Excel 风格时间文本 |
| `0x1400B3BE0` | SQLite 导出 | metadata / records 两张表，字段与 CSV 对应 |
| `0x1400E0810` | 时间显示 | 一天内 `hh:mm:ss.mmm`，超过一天有 `D.` 前缀 |

这些是原生 VA，不是 .NET RID；IDA 自动推断的 Qt 参数类型尚不可靠。完整来源与上游 MIT 字段定义交叉核对见 [调查](../docs/k2-monitor-research.md)。

## 数据在三层之间流动

```text
普通模式 HID 报告
  → 帧长 / 命令 / 载荷 / 双校验检查
  → 原始读数字段：电压、有符号电流、温度、D±、设备 Ah / Wh、秒数
  → 电脑采样与分段记录：暂停不保存，恢复新分段，不补造缺失样本
  → 本地完整 SQLite / CSV 与官方形式 SQLite
  → 区间统计和有界绘图查询
```

设备累计量不是电脑本次积分值；有符号电流不是非负显示功率；缺失外部探头不是有效零温度。数据层保留这些区分，交换层按相应文件约定输出。

## 关键格式

普通报告的有效字段包括：偏移 14 / 18 的 float32 Ah / Wh，22 / 26 的 uint32 记录 / 开机秒数，30 / 34 的 D±，38 / 42 的内部 / 外部温度，46 / 50 的电压 / 电流，54 的记录组。全表见 [调查](../docs/k2-monitor-research.md#官方程序证据)。

CSV 元信息为 `SUM`、`TotalTime`、`SampTime(ms)`、`DateTime`；必选列为时间、电压、电流、功率，可选温度和 D±。官方 SQLite 的 `metadata` 保存这些键，`records` 的数值由官方以 TEXT 保存。时间字符串、BOM、尾逗号及可选列处理见原调查与 `k2up/recording_files.py`。

## 从静态推断到实机确认

最初静态代码与上游驱动未严格检查遥测双校验，不能仅因 DFU 有双校验就推断遥测也一样。后续 K2 5.8 的 1201 个报告实机只读捕获确认头、命令、52 字节载荷与双校验；之后实现启用该检查。

旧 100 Hz 采样以每次到达重新推迟截止时间，导致漂移；改为固定经过时间区间后，历史打包后台一分钟记录保存 6015 样本，约 100.002074 样本 / 秒。结果来自特定设备与版本，详细记录见 [实测](../docs/k2-monitor-hardware-validation.md)。

`test_telemetry.py`、`test_monitor.py`、`test_recording.py`、`test_recording_stats.py` 分别覆盖解析、控制、交换和统计。已有文件往返是本应用导出后重新导入，不是 Windows 官方程序往返；官方实样、有负载方向全面验证和其他固件仍有缺口。

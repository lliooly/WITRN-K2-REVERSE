# 02：固件格式、HID 与升级事务

## 核心结论及来源

| 结论 | 证据位置 | 独立实现 |
| --- | --- | --- |
| `.k2` 要先做逐字节替换，再解析 48 字节头 | 导出替换表、固件样本检查和 UP V30 静态分析 | `k2up/firmware.py` |
| 擦除计算包含整个容器长度，写入只使用应用正文 | UP V30 RID 440 向 RID 165 传递容器长度；详见原协议及源码注释 | `Firmware.erase_addresses` |
| 升级包含完整读回、最后提交、结束 ACK | 重点 C# worker RID 439、代理映射与常量分析 | `k2up/updater.py` |
| 擦写和批量读复用底层封装 | RID 145 / 148 / 154 及相关调用 | `k2up/protocol.py` |
| 短读和大批量读不等于更高 USB 带宽 | 特定 Bootloader 静态分派与三轮只读测速 | `reverse/benchmark_dfu_reads.py` |

RID 439 是重点导出文件中的 worker；RID 440 是相邻方法，不能混为同一个函数。具体方法限定名和恢复定位见 [函数索引](functions/README.md)。这里的职责标签不意味着完整还原了全部控制流分支。

## 三种长度必须分开

- 容器长度：48 字节头部 + 应用正文；原升级器按此计算擦除扇区数。
- 写入长度：仅应用正文，自 `0x08003800` 开始。
- 分配上限：447 × 2048 字节，自应用起点到 `0x080E3000`（不含）。这不是固件样本总会占用的长度。

5.8 样本正文为 716400 字节，容器为 716448 字节，对应 350 个 2 KiB 擦除扇区。头部字段、GUID、小端格式、向量与哈希见 [完整协议](../docs/protocol.md#固件容器) 和 [样本摘要](../evidence/firmware-5.8-summary.json)。

## 帧与操作顺序

HID 主帧 64 字节，头为 `FF 55`，命令在偏移 8、负载长度在偏移 9、负载空间为 52 字节。两项校验分别为 `sum(frame[8:62])` 和 `sum(frame[:62])` 的低 8 位；后者不把偏移 62 的内层校验加入和。

```text
离线校验固件
  → 命令 3 握手 → 读取信息及名称 → 核对 K2
  → 命令 22 清理日志状态
  → 5 开批次 → 8 逐扇区擦除 → 4 关批次
  → 5 开批次 → 9 分包写入正文 → 4 关批次
  → 11 完整读回正文并逐字节比较
  → 写提交值 FE FF FF FF → 读回核对
  → 23 结束会话并确认 ACK
```

正文提交标记偏移为 `0xC00`，绝对地址为 `0x08004400`。控制命令 ACK 与数据分包行为不同；写入包最多 40 字节数据。完整命令表与事务限制见 [协议](../docs/protocol.md#命令)。异常立即停止的规则来自独立实现及失败测试，不能自动等同于厂商所有错误分支。

## 共用地址关系

| 区域 | 起点 | 与其他主题的关系 |
| --- | --- | --- |
| 名称区 | `0x08001400` | 身份核验，不在应用正文内 |
| 设备信息 | `0x08003000` | 升级探测使用 |
| 应用正文 | `0x08003800` | 起点固定，实际结束随正文长度变化 |
| 背景图 | `0x080C6800` | 位于完整应用备份范围内；不意味着任意固件都写到该位置 |
| E-Mark 复制 / 集合 | `0x080E3000` / `0x080E3800` | 超出既有完整应用备份范围 |
| 表盘参数 / 开机图 | `0x080E4000` / `0x080E4800` | 需要独立资源备份 |

## 验证边界

`tests/test_k2up.py` 覆盖格式、帧、顺序、错误停止、身份核验和合成备份；`tests/test_dfu_read_benchmark.py` 检查只读命令限制及数据完整性。历史单台 K2 的 3.4 → 5.8 升级有读回与提交结果，但恢复容器回刷和其他版本未实测。大请求的节省时间仅有读取实验和全流程推算，没有完整升级测速。XOR / 加法和不是来源认证。
